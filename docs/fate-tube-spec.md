# 签筒（命运牌 · 明签模式）规格草案 v0.1

> 状态：**v1 已实现**（在本仓库内）。源码基线：sillytavern-perf-lab `6f8435f`（命运牌独立插件拆分后），插件版本 1.3.0。
>
> 与设计的差异（实现时裁定）：
> - 开关放在命运牌面板的「⚙ 命运牌设置」里（盲牌的既有设置都在面板中，保持一处），扩展设置抽屉不再另加复选框；
> - 运势入账与本命运牌完成事件处理器合并执行，避免同一条回复上两个写入方互相覆盖；
> - 「展开成事件」（把签文扩写成 ≤400 码点的完整事件）为二期，v1 采用即注入签文本身；
> - 求筒经运行时的隔离请求通道（`isolated: true`），官方 1.19.0 与 perf-lab 皆不触碰正文钩子与长度设置。
> 一句话：把"看方向"和"付成本"解耦——一次小请求买一筒明签，摇签本地免费但有"运"作价，采用后经现有命运牌事件路径注入。

## 1. 定位

- 解决的痛点：预设给的走向全不满意、又不想重新生成正文时的"卡住"；以及盲牌"仅一次换组"过紧、无限重摇又失重的两难。
- 与盲牌的关系：同一个 🎴 面板里的第三个 tab（现牌 | 本局 | **签筒**）。盲牌服务"让命运决定"的心情，签筒服务"我要自己挑，但给我更多材料"的心情。两套经济学互不改动。
- 注入发生之前，主生成零改动。签文在采用之前只是本地数据。

## 2. 开关与设置

- `extensionSettings.director.fate.tube = { enabled: boolean }`，默认 `true`。
- Seeding 与校验照抄 affinity 模式（`index.js` init 中 `settings.affinity` 的现有写法）：非对象则重置、非布尔则回默认。
- UI：设置抽屉「🎴 命运牌」区域内一个复选框「签筒」，样式对齐 `director_affinity_enabled`。
- 关闭行为：隐藏签筒 tab、停用运势监听；**已存的池与运势保留在元数据里不删除**（重新打开原样恢复）。除此之外没有任何二级设置——保持薄。

## 3. 与正文的隔离（全部沿用现有机制，零新协议）

签筒自身不新增任何注入代码：**采用一支签 = 用签文创建一次现有命运牌事件绑定**，此后走 `fate.prepare` 的既有路径：

| 层 | 机制 | 现有实现 |
| --- | --- | --- |
| 存储 | 签池/运势存 `chat_metadata.director.fate.tube`；正文消息与存档不含签文 | 同盲牌事件存 `director.fate` |
| 注入 | 私有区定界符 + `{}<>\r\n` 保护 + narrator 请求副本 | `fate.js` prepare 的 `\uE000…\uE003` shield |
| 还原 | `GENERATE_AFTER_DATA` 字面替换；未知 frame 整段清除 | 现有 listener |
| 扫描 | 世界书扫描排除 `directorFatePrompt` 行 | `script.js` chatForWI 过滤 |
| 界面 | 采用的消息沿用现有 fate 印记（fate-marks） | 无改动 |

签文长度远小于盲牌事件（≤60 码点 vs 400），绑定/沿用/编辑撤回语义与盲牌完全一致（swipe、regenerate 沿用，指纹不符失效）。

## 4. 运势（每聊天一份）

存储：`director.fate.tube.luck`，整数 0–10，初始 10。版本字段 `tube.version = 1`。

| 事件 | 变化 |
| --- | --- |
| 摇一次（翻出 ≤3 支未看过的签） | −1 |
| 一条**有效新回复**完成 | +1（不超上限） |
| 标记新章节起点 | 回满至 10 |

- **有效新回复**沿用好感度凭据语义：normal 与 swipe 完成各 +1；regenerate / continue 不加（没有新内容）。复用现有完成事件监听，不新增事件源。
- **"看"永远免费**：已看过的签随时免费回看（列表常驻）；运为 0 时不能翻新签，但绝不阻断任何操作——旧签随便看、正文随便写。
- 运势不足摇新签时按钮显示「运不足——先让故事走一步」，不弹窗。
- 切聊天各管各的运；不跨聊天共享。

## 5. 求筒（唯一会发请求的动作）

- 触发：筒内无未看签时点「再求一筒」；或首次打开 tab 且无池。
- 请求：**隔离旁路** `generateQuietPrompt({ isolated: true, jsonSchema, maxOutputTokens: 768, signal })`——注意盲牌现行事件请求走的是旧路径（`fate.js:354`，非隔离 + `responseLength`）；签筒只用新路径，绝不碰 `TempResponseLength` 与 CC/TC 设置事件。
- Schema：`{ sticks: [12] }`，每支 `{ category, rarity, text }`；`category` ∈ `fate-decks.js` 现有 12 类；`rarity` ∈ common/rare/legendary；`text` ≤60 Unicode 码点、无控制字符、彼此不同。严格校验，任何一项不合格整筒拒绝（fail-closed，同 affinity 的解析纪律）。
- 输入：
  - 最近 ≤8 条消息文本，超长按 head/tail 摘录截断（复用 budget 模块的 excerpt 思路）；
  - 负面清单：最近拒绝的 ≤12 支签文，一行"避免与这些类似的走向"；
  - 固定指令：12 支尽可能彼此不同、覆盖不同干预类型（外部事件/角色主动/代价/换幕/约束各至少一支）、避开最近剧情的惯性走向、中文口语、尊重既有边界句（不推动恋爱、亲密或服从）。
- 节流：全后台同一时刻最多一条求筒在途；正文生成中禁用求筒按钮；切聊天 / 新正文开始 → abort 在途请求的 signal。
- 失败：保留旧筒与运势，按钮恢复，不静默重试、不循环。
- 拒签（点"不要"或直接摇过）：签文进入负面清单（cap 12，FIFO）；求新筒成功后清空。

## 6. 摇与采用

- 摇：从筒内**未看过**的签中随机翻 3 支（不足 3 支时翻出剩余并禁用摇）；动画/音效复用 fate-ui 与 fate-sound。摇历史 = 已看列表，免费回看。
- 采用：签文经现有事件绑定路径注入下一笔；被采用的签标记已用；**筒内其余签随采用作废**（求筒时清空）——"一筒换一支"是明面上的规则。
- 可选「展开」：以签文为种子走一次盲牌式事件生成（≤400 码点），给想要完整事件的人；默认不展开，注入的就是这一句话。
- 采用不可反悔（与盲牌一致）；swipe/regenerate 沿用同一签文。

## 7. 边界与失败

- 空聊天 / 聊天加载中：禁用求筒与采用。
- 元数据损坏：`tube` 不合版本 → 整体重置签池与运势（fail-closed），**绝不触碰正文与其他 director 数据**（同 affinity 的 `state()` 校验风格）。
- 导出/分享聊天文件包含签池与已用签明文——与盲牌同一定位：盲抽不是加密。
- 移动端 390px：tab、运势点、摇/求筒按钮 ≥44px 高，不横向溢出（对齐盲牌现有验收标准）。

## 7a. 真实场景验收（2026-11-08，已通过）

宿主：sillytavern-perf-lab `6f8435f`（内置命运之笔停用），ZIP 安装 `st-director-fate-cards` 1.3.0；
连接：OpenAI 兼容中转站 + `gemini-3.1-flash-lite` 级别小模型（真实密钥仅经环境变量/数据根 secrets.json，不入仓库）。
Playwright 有头 Chrome 驱动，全新数据根走完整首启流程。11/11 步通过，页面异常 0：

1. 应用加载（首启欢迎弹窗自动确认）；
2. 拦截器归属：内置 `director_rebind_interceptor` 未注册，插件 `standalone_director_cards_interceptor` 就位，命运牌入口恰一个；
3. 真实连接（自定义端点 + 掩码密钥）；
4. 真实模型首条回复；
5. 求一筒（真实模型调用，12 支明签，覆盖不同干预类型）；
6. 摇一摇（运气 10→9，翻出 3 支）；
7. 上签（签文变成已上手的命运牌）；
8. 让意外发生（真实生成，注入签文）；
9. 绑定证据（本局命运日志 1 条 + 消息印记 1 枚）；
10. 运势回充（回复 +1 后回到满 10）；
11. 第二轮：旧筒作废 → 求新筒 → 摇签 → 拒签一支 → 再求新筒 → 摇光 12 支核对，被拒签文不再出现。

真实运行同时修正一处设计偏差并补测试：上签后余签作废——关闭的筒不可再摇（控制器与视图双重门禁 + 单测）。
自动化脚本：`tests/browser-tube-real.py`（密钥与中转站地址仅经环境变量或命令行传入）。

## 8. 测试要点（全部离线可测）

1. 运势：摇扣、有效回复回充、regen/continue 不回充、上限、章节回满、切聊天隔离、损坏重置。
2. 求筒：schema 拒绝样例（多字段/超长/重复/未知类别）、在途节流、abort 清理、失败保留旧筒、负面清单注入内容断言（拦截请求体断言）。
3. 采用：绑定生成、swipe/regen 沿用、编辑撤回、采用后余签作废、印记同步到每个 swipe。
4. 开关：关闭隐藏 tab、监听停用、池保留、重开恢复。
5. 隔离：求筒请求不触发 `CHAT_COMPLETION_SETTINGS_READY` / `TEXT_COMPLETION_SETTINGS_READY`、不消耗 `TempResponseLength`、正文事件不等待求筒 promise。
6. 浏览器实验室：新增 `tube` 用例组（求筒→摇→采用→正文注入→运势变化），390×844 布局快照。

## 9. 明确不做的

- 不做口味指纹、不做自动诊断、不做后台种子（前几轮讨论已裁掉）。
- 不改盲牌现有经济（换一次、保底、稀有度权重）。
- 不新增设置项 beyond 开关。
- 不迁移盲牌旧请求路径（另行处理，与本规格解耦）。
